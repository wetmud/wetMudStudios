# leadgen-crm

Node.js + Express CRM for reviewing and acting on leads generated by `leadgen-scraper`. Split-panel interface: lead list on the left, detail + outreach on the right.

## Setup

```bash
npm install
export ANTHROPIC_API_KEY=your_key_here
```

## Run

```bash
node server.js
# Open http://localhost:3000
```

## Features

- **Lead list** — sorted by score, filterable by city, niche, status, score range; search by name
- **Lead detail** — all scraped signals, score breakdown, status dropdown (auto-saves), notes (auto-saves on blur)
- **Draft outreach email** — one click calls Claude Haiku with lead context; drafts are cached; regenerate available
- **NEW pill** — newly scraped leads are flagged; cleared on first view

## API

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/leads` | List leads (filter: city, niche, status, min_score, max_score, search) |
| GET | `/api/leads/:id` | Get lead + outreach; clears is_new flag |
| PATCH | `/api/leads/:id` | Update status and/or notes |
| POST | `/api/leads/:id/draft` | Get or generate outreach email draft (`?regenerate=1` to force new) |
| GET | `/api/meta` | Distinct cities and niches for filter dropdowns |

## Auth (optional)

Set `ACCESS_TOKEN` env var to require `Authorization: Bearer <token>` on all API requests. Intended for Railway deploys.

## Database

Reads `leads.db` from the parent directory (shared with the scraper). Uses WAL mode on every connection.

## Tests

```bash
npm test
```

11 tests covering all API endpoints. Tests use an isolated temp database — no production data touched.
