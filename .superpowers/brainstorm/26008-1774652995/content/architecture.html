System Architecture — Option B

Two independent pieces sharing a SQLite database

🔍 Piece 1 — Scraper CLI (runs locally)
Python + Playwright
python scrape.py --city Burlington --type restaurant

Data sources:
→ Google Maps (primary)
→ Yellow Pages / Canada411 (enrichment)

Scoring engine:
→ No website → +40pts
→ No Google listing → +30pts
→ Wix/Squarespace/template site → +20pts
→ Few/old reviews → +10pts
→ Business type match → +10–20pts
→ Broken/no SSL → +10pts

Output: writes leads → leads.db (SQLite)
⇄
📋 Piece 2 — CRM App (Node.js + Express)
Reads from leads.db

CRM views:
→ Lead list (sortable by score)
→ Lead detail (all scraped data + score breakdown)
→ Status pipeline (New → Contacted → Replied → Won/Lost)
→ Filter by city, niche, score range

Outreach:
→ "Draft email" → calls Claude API → personalized pitch
→ Copy to clipboard or (later) send via Gmail

Deploy: Railway or run locally
Frontend: Vanilla HTML/CSS/JS (no framework)
🗄️ Shared — leads.db (SQLite)
leads table
id, name, address, city, niche
phone, email, website_url
google_listing (bool)
site_platform (wix/wp/none/etc)
review_count, last_review_date
score, score_breakdown (JSON)
scraped_at
outreach table
id, lead_id
status (new/contacted/replied/won/lost)
email_draft (text)
notes
contacted_at, updated_at
